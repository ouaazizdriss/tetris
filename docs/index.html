Four states, one switch

Every action method starts with activePiece(), which returns the piece only while the state is PLAYING. Pausing is therefore a single assignment: input and gravity both stop on their own.

READY→ start() →PLAYING⇄ pause() / resume() ⇄PAUSED
PLAYING→ spawn blocked or lock above row 0 →GAME_OVER

After a game over, the view ignores taps for 700 ms (RESTART_GUARD_MS) so a last hard drop does not restart the game by accident.

private fun activePiece(): ActivePiece? = if (state == State.PLAYING) current else null
internal fun spawn(type: Tetromino) {
    val p = ActivePiece(type, (COLS - type.size) / 2, if (type == Tetromino.I) -1 else 0, 0)
    gravityAccum = 0f
    lockTimer = 0f
    lockResets = 0
    lowestY = p.y
    if (!fits(p.type, p.x, p.y, p.rotation)) {
        current = null
        gameOver()
        return
    }
    current = p
}

ROTATIONTetrisGame.kt · lines 14–25, 140–159, 283–303

Four orientations from one spawn shape, and five chances to fit.

Each piece is declared once, in its SRS spawn orientation inside a square box. The other three states come from rotating the box clockwise: a cell at (x, y) moves to (size − 1 − y, x). A rotation then tries up to five offsets from the SRS kick table and keeps the first one that fits.

    J(0xFF3B82F6.toInt(), 3, cells(0, 0, 0, 1, 1, 1, 2, 1)),
    L(0xFFF97316.toInt(), 3, cells(2, 0, 0, 1, 1, 1, 2, 1)),
    O(0xFFFACC15.toInt(), 2, cells(0, 0, 1, 0, 0, 1, 1, 1)),
    S(0xFF22C55E.toInt(), 3, cells(1, 0, 2, 0, 0, 1, 1, 1)),
    T(0xFFA855F7.toInt(), 3, cells(1, 0, 0, 1, 1, 1, 2, 1)),
    Z(0xFFEF4444.toInt(), 3, cells(0, 0, 1, 0, 1, 1, 2, 1));

    val rotations: List<List<Cell>> =

The O piece is never rotated: rotate() returns false for it before looking at a table.

The kick tables

Two tables, keyed by from * 4 + to: one for J, L, S, T and Z, one for I. Each row holds five (x, y) tests, written y-up as in the SRS specification. The board grows downward, so the code flips the sign: val ky = -kicks[i + 1]. Eight transitions per table, five tests each: 80 offsets.

SRS wall kick offsets
fun rotate(direction: Int): Boolean {
    val p = activePiece() ?: return false
    if (p.type == Tetromino.O) return false
    val to = (p.rotation + direction).mod(4)
    val table = if (p.type == Tetromino.I) I_KICKS else JLSTZ_KICKS
    val kicks = table.getValue(p.rotation * 4 + to)
    for (i in kicks.indices step 2) {
        // Kick tables are written y-up, the board is y-down.
        val kx = kicks[i]
        val ky = -kicks[i + 1]
        if (fits(p.type, p.x + kx, p.y + ky, to)) {
            p.x += kx
            p.y += ky
            p.rotation = to
            onManipulated(p)
            return true
        }
    }
    return false
}

    7-BAGTetrisGame.kt · lines 64–65, 216–219

    Seven pieces to a bag, shuffled, and the queue never runs dry.

    The queue is refilled with a shuffled copy of all seven tetrominoes whenever it holds three pieces or fewer, so the three-piece preview is always full. Within any bag every piece appears once, so at most 12 other pieces can come between two of the same kind.

    private fun nextFromQueue(): Tetromino {
    while (queue.size <= PREVIEW) queue.addAll(Tetromino.entries.shuffled(random))
    return queue.removeFirst()
}

    Hold swaps the current piece with the held one, or takes the next from the queue on the first hold. It is allowed once per piece: canHold goes false on hold and back to true when the next piece locks.

    Lock delay: 500 ms, 15 resets

    Once a piece cannot fall, a 500 ms timer runs. A successful move or rotation resets it, up to 15 times. Reaching a new lowest row clears that count, so a piece that keeps sinking can keep sliding; one that spins in place locks.

    private fun trackLowest(p: ActivePiece) {
    if (p.y > lowestY) {
        lowestY = p.y
        lockResets = 0
    }
}

private fun onManipulated(p: ActivePiece) {
    trackLowest(p)
    if (lockTimer > 0f && lockResets < MAX_LOCK_RESETS) {
        lockTimer = 0f
        lockResets++
    }
}

      Standard Gradle Android project: Kotlin targeting Java 17, compileSdk 36. Release signing reads a keystore.properties file at the project root that is not committed; without it the release APK is built unsigned.
